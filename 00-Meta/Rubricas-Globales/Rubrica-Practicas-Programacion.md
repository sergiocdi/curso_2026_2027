# 📊 Rúbrica General de Prácticas y Proyectos de Programación

| Criterio / Dimensión | Insuficiente (0 - 4.9) | Suficiente / Bien (5 - 6.9) | Notable (7 - 8.9) | Sobresaliente (9 - 10) | Ponderación |
| :--- | :--- | :--- | :--- | :--- | :---: |
| **1. Corrección Funcional** | El código no compila, contiene errores críticos de ejecución o no cumple los requisitos mínimos. | Cumple la mayor parte de requisitos funcionales básicos, con fallos menores en casos particulares. | Cumple todos los requisitos funcionales obligatorios de forma robusta y correcta. | Cumple todos los requisitos obligatorios y los opcionales/avanzados con excelente comportamiento. | **40%** |
| **2. Arquitectura y Código Limpio** | Código desordenado, sin capas ni modularidad, variables sin sentido, código espagueti. | Estructura comprensible, uso aceptable de funciones/clases, nombres de variables mejorables. | Buena separación de responsabilidades, convenciones de nombres estándar, código modular y legible. | Arquitectura ejemplar (DAO, Repositorios, Patrones), principios SOLID aplicados, sin código duplicado. | **25%** |
| **3. Manejo de Errores y Excepciones** | No captura excepciones o usa bloques `catch` vacíos ignorando fallos. La app se cae con entradas erróneas. | Maneja excepciones básicas pero los mensajes al usuario son crípticos o poco informativos. | Captura y gestiona adecuadamente las excepciones esperadas, liberando recursos (try-with-resources). | Gestión exhaustiva y profesional: logs de error, excepciones personalizadas y recuperación fluida. | **15%** |
| **4. Control de Versiones (Git) y Flujo de Trabajo** | Un único commit final masivo ("subo todo") o mensajes sin significado. | Pocos commits, mensajes poco descriptivos, sin uso de ramas de trabajo. | Historial de commits ordenado y regular, mensajes explicativos y uso de `.gitignore`. | Flujo Git profesional (ramas por funcionalidad, commits atómicos semánticos, README impecable). | **10%** |
| **5. Documentación y Entrega** | No incluye README ni explicaciones para ejecutar o probar la aplicación. | Incluye instrucciones mínimas pero incompletas o confusas. | README claro con requisitos previos, comandos de ejecución y datos de prueba. | Documentación sobresaliente con capturas, diagramas de clases/E-R y manual de usuario/desarrollador. | **10%** |
