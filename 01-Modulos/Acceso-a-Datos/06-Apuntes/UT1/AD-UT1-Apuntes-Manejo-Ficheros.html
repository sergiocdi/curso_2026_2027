1 Introducción Contextualizada y Persistencia

En cualquier sistema informático profesional, los datos almacenados en variables o estructuras en memoria RAM (objetos, arrays, colecciones) tienen un ciclo de vida efímero: desaparecen en cuanto la aplicación finaliza su ejecución, el proceso es detenido o el servidor físico se reinicia. Para conseguir que la información trascienda en el tiempo, es imprescindible implementar mecanismos de persistencia en medios no volátiles de almacenamiento secundario (discos de estado sólido SSD, discos duros mecánicos HDD o volúmenes de red NAS/SAN).

🏭 Utilidad Real en el Mundo Profesional

Aunque en cursos posteriores y proyectos de gran envergadura la persistencia principal recae sobre Sistemas Gestores de Bases de Datos Relacionales (SGBD) o motores NoSQL, el manejo de ficheros a bajo nivel continúa siendo la columna vertebral técnica de:
• Registros de auditoría del sistema (Logs): Generación y rotación de trazas de eventos en servidores web (Apache, Nginx) y microservicios con Logback o Log4j2.
• Ficheros de configuración de entornos: Parámetros de arranque del aplicativo en formatos de texto plano (.properties, .env, .yaml, .json).
• Procesos ETL (Extract, Transform, Load) e Ingesta Masiva: Descarga, análisis y consolidación masiva de millones de registros estructurados en ficheros delimitados (CSV, TSV).
• Intercambio Seguro B2B y Facturación Electrónica: Integración entre entidades públicas y bancarias mediante esquemas estándar XML (formato oficial Facturae, SEPA ISO 20022).

¿Qué conocimientos previos necesitas? Para seguir con éxito esta unidad formativa debes dominar los fundamentos de Programación en Java de 1º de DAM:

  • Programación orientada a objetos: definición de clases, constructores, atributos, visibilidad y métodos.
  • Uso de colecciones básicas de la Java Collections Framework: List, ArrayList y Map.
  • Gestión estructurada de excepciones mediante bloques try-catch-finally y propagación de errores con la cláusula throws.

2 Conceptos Fundamentales de I/O y Streams

2.1. La Metáfora Intuitiva del Stream (Flujo de Datos)

Para entender cómo se comunican las aplicaciones con el disco, piensa en una tubería de agua que conecta un embalse con un grifo. Tú no abres el grifo y recibes todo el volumen del embalse de golpe en una milésima de segundo; el agua viaja de manera continua, gota a gota o litro a litro, a través de la tubería.

En Java, un Stream (Flujo) es exactamente esa tubería: una secuencia ordenada, secuencial y unidireccional de datos que conecta un origen (fuente) con un destino (sumidero). La gran ventaja conceptual del flujo es que **abstrae por completo el hardware**: para tu código Java, leer 100 bytes de un archivo local en un disco SSD, leerlos desde un puerto de red TCP o recibirlos del teclado utiliza exactamente las mismas llamadas a métodos.

2.2. Las Dos Grandes Jerarquías: Bytes frente a Caracteres

El paquete fundacional de Java (java.io) divide todos los flujos en dos árboles de clases completamente separados según el tipo elemental de dato que transportan:

Criterio de Clasificación Flujos de Bytes (8 bits / Binarios) Flujos de Caracteres (16 bits / Unicode)
Unidad mínima de datos byte (8 bits, valores de -128 a 127 / 0 a 255). char (16 bits, código Unicode UTF-16).
Clase base de Entrada (Lectura) java.io.InputStream java.io.Reader
Clase base de Salida (Escritura) java.io.OutputStream java.io.Writer
Tipo de contenido idóneo Imágenes (PNG, JPG), audio, ejecutables, PDFs, ficheros compilados .class. Texto legible por humanos: archivos .txt, .csv, código fuente, .xml, .json.
Conversión de codificación No aplica: los bytes se leen o escriben tal cual están físicamente. Aplica traducción de bytes a caracteres usando un Charset (juego de caracteres).

2.3. Memoria Intermedia (Buffer) y el Patrón Decorador

Acceder a un dispositivo de almacenamiento físico es miles de veces más costoso en tiempo de CPU que operar en la memoria RAM. Si tu programa lee un archivo carácter a carácter invocando un método de disco en cada iteración, la JVM debe solicitar continuas interrupciones al sistema operativo (cambios de contexto de modo usuario a modo kernel), degradando el rendimiento de forma crítica.

💡 El Búfer en Memoria y el Patrón Decorador

Un Búfer es un bloque de memoria RAM de alta velocidad (típicamente de 8192 bytes / 8 KB) que actúa como almacén intermedio. Cuando pides el primer carácter, el sistema lee de golpe 8192 caracteres del disco y los guarda en RAM. Las siguientes 8191 lecturas se realizan instantáneamente desde la memoria sin tocar el disco.
Java implementa esto mediante el Patrón Decorador: tomas un flujo básico de bajo nivel (por ejemplo FileReader) y lo envuelves dentro de una clase decoradora que añade el búfer transparente (BufferedReader).

2.4. Gestión de Recursos del Sistema Operativo: try-with-resources

Cada vez que abres un fichero, el núcleo del sistema operativo reserva un descriptor de fichero (file handle) en su tabla interna de procesos. Este recurso es limitado por el kernel (a menudo 1024 ficheros abiertos simultáneos en Linux). Si un programa en bucle abre flujos y no los cierra debidamente, se produce una **fuga de recursos (resource leak)**, bloqueando el archivo en Windows e impidiendo que el servidor abra nuevas conexiones o ficheros con el error fatal:

java.io.IOException: Too many open files

Para erradicar este problema, desde Java 7 se utiliza la sentencia try-with-resources. Cualquier objeto instanciado dentro del paréntesis del try (...) que implemente la interfaz java.lang.AutoCloseable garantizará la ejecución de su método close() de forma automática y ordenada al salir del bloque, incluso si ocurre una excepción grave no controlada.

3 Desarrollo Progresivo y Exhaustivo por Temas

3.1. Ficheros de Texto Plano con la API Clásica (java.io)

Analicemos individualmente las clases fundamentales de la biblioteca clásica java.io, sus métodos más usados, ejemplos de código funcional y sus casos de aplicación práctica.

A. Clase java.io.File

Concepto: Representación abstracta del nombre y la ruta de un archivo o directorio en el sistema de archivos local. No permite leer ni escribir el contenido del archivo; sirve exclusivamente para consultar metadatos y realizar operaciones sobre el sistema de ficheros.

Instrucciones y Métodos Más Usados:

  • boolean exists(): Retorna true si el archivo o carpeta existe físicamente en el disco.
  • boolean isFile() y boolean isDirectory(): Verifican si el elemento es un archivo regular o una carpeta.
  • String getName(): Retorna el nombre simple del fichero con su extensión (ejemplo: "datos.txt").
  • String getAbsolutePath(): Retorna la ruta completa normalizada desde la raíz del sistema.
  • long length(): Devuelve el tamaño físico del archivo en bytes (para directorios retorna un valor indefinido).
  • boolean createNewFile() throws IOException: Crea un nuevo archivo vacío de forma atómica; retorna true si se creó con éxito.
  • boolean mkdir() y boolean mkdirs(): Crea la carpeta. mkdirs() crea además todos los directorios padres intermedios que no existan.
  • boolean delete(): Borra el archivo o carpeta. Para borrar una carpeta, esta debe estar completamente vacía.
  • File[] listFiles(): Retorna un array con todos los archivos y subcarpetas que contiene el directorio.
GestionMetadatosFile.java JAVA 21 
import java.io.File;
import java.io.IOException;

public class GestionMetadatosFile {
    public static void inspeccionarRuta(String ruta) {
        File f = new File(ruta);
        
        System.out.println("Ruta analizada: " + f.getAbsolutePath());
        if (f.exists()) {
            System.out.println("¿Es directorio?: " + f.isDirectory());
            System.out.println("¿Es archivo?: " + f.isFile());
            System.out.println("Tamaño físico: " + f.length() + " bytes");
            System.out.println("Permisos - Lectura: " + f.canRead() + " | Escritura: " + f.canWrite());
        } else {
            System.out.println("El elemento no existe en disco.");
        }
    }
}

B. Clases FileReader y FileWriter

Concepto: Flujos de conexión directa con disco físico para leer y escribir caracteres.

Instrucciones y Métodos Más Usados:

  • new FileReader(File archivo, Charset charset): Abre el fichero para lectura especificando el juego de caracteres obligatorio.
  • int read(): Lee un único carácter y lo devuelve como un int (su código Unicode de 0 a 65535). Retorna -1 al alcanzar el final del archivo (EOF).
  • int read(char[] cbuf): Lee un bloque de caracteres y los almacena en el array cbuf, retornando la cantidad leída.
  • new FileWriter(File archivo, Charset charset, boolean append): Abre el archivo para escritura. Si append es true, añade al final sin borrar el contenido existente.
  • void write(String str): Escribe una cadena de texto completa.
  • void flush(): Fuerza el vaciado inmediato de los datos en disco físico.

C. Clases Decoradoras: BufferedReader y BufferedWriter

Concepto: Envuelven a un Reader o Writer añadiendo una memoria intermedia de 8 KB. Proporcionan métodos de alto nivel orientados al tratamiento por líneas de texto.

Instrucciones y Métodos Más Usados:

  • String readLine() throws IOException: Lee una línea completa de texto. Descarta automáticamente los delimitadores de salto de línea (\r o \n). Devuelve la cadena o null si se ha alcanzado el Fin de Fichero (EOF).
  • void newLine() throws IOException: Escribe el salto de línea adecuado según el sistema operativo donde corre el programa (CRLF en Windows, LF en Linux/macOS).
CopiaBufferSegura.java JAVA 21 
import java.io.*;
import java.nio.charset.StandardCharsets;

public class CopiaBufferSegura {
    public static void copiarConFiltro(File origen, File destino, String prefijoFiltro) {
        // Bloque try-with-resources: asegura el cierre implícito de ambos flujos
        try (
            BufferedReader br = new BufferedReader(new FileReader(origen, StandardCharsets.UTF_8));
            BufferedWriter bw = new BufferedWriter(new FileWriter(destino, StandardCharsets.UTF_8))
        ) {
            String linea;
            int numLinea = 1;
            
            // Patrón estándar de lectura línea a línea en Java
            while ((linea = br.readLine()) != null) {
                if (linea.startsWith(prefijoFiltro)) {
                    bw.write("[" + numLinea + "] " + linea);
                    bw.newLine(); // Salto de línea portable
                }
                numLinea++;
            }
            // Al cerrarse el bloque se ejecuta automáticamente bw.flush() y bw.close()
        } catch (FileNotFoundException e) {
            System.err.println("Error: Archivo de origen no localizable: " + e.getMessage());
        } catch (IOException e) {
            System.err.println("Error crítico de Entrada/Salida: " + e.getMessage());
        }
    }
}

3.2. La Revolución de la API Moderna Java NIO.2 (java.nio.file)

Introducida en Java 7 y consolidada en las versiones modernas de Java SE, la biblioteca NIO.2 reemplaza los defectos estructurales de java.io.File aportando soporte multiplataforma completo, manejo atómico de archivos y programación funcional mediante Streams.

A. Interfaz java.nio.file.Path y Métodos Factoría

Concepto: Objeto inmutable que representa la localización de un fichero en el árbol de directorios de manera agnóstica al sistema operativo.

Instrucciones y Métodos Más Usados:

  • Path.of(String primero, String... mas): (Recomendado en Java 11+) Construye un Path ensamblando las partes sin importar si el SO usa barras inclinadas / o invertidas \.
  • Path getFileName(): Retorna el nombre final del recurso.
  • Path getParent(): Retorna la ruta del directorio contenedor.
  • Path toAbsolutePath(): Resuelve la ruta relativa respecto al directorio de trabajo actual de la aplicación.
  • Path normalize(): Elimina redundancias como puntos individuales . (directorio actual) y dobles puntos .. (directorio padre).
  • Path resolve(String otraRuta): Concatena dos rutas de forma segura.
  • Path relativize(Path origen): Calcula la ruta relativa necesaria para desplazarse desde un Path hasta otro.

B. Clase de Utilidad java.nio.file.Files

Concepto: Clase estática compuesta enteramente por métodos de utilidad que operan directamente sobre objetos Path. A diferencia de java.io.File (que devolvía false cuando algo fallaba en silencio), Files lanza excepciones precisas y descriptivas (NoSuchFileException, DirectoryNotEmptyException, FileAlreadyExistsException).

Operaciones del Sistema de Archivos:

  • boolean exists(Path p): Verifica existencia.
  • Path createDirectories(Path p): Crea toda la jerarquía de directorios inexistentes.
  • void delete(Path p) throws IOException: Borra el fichero o lanza excepción si no existe.
  • Path copy(Path origen, Path destino, CopyOption... opciones): Copia el fichero. Permite la opción StandardCopyOption.REPLACE_EXISTING para sobreescribir.
  • Path move(Path origen, Path destino, CopyOption... opciones): Mueve o renombra. Con StandardCopyOption.ATOMIC_MOVE asegura que la operación no deje archivos a medio escribir ante caídas de corriente.
  • long size(Path p): Retorna el tamaño exacto en bytes.

C. Métodos Atómicos de Lectura y Escritura en Files

Para archivos de tamaño pequeño o moderado (menos de 20-50 MB), Files resuelve la lectura o volcado en una única línea de código, abriendo y cerrando los descriptores de forma automática:

  • String readString(Path ruta, Charset cs): Lee todo el archivo y lo vuelca directamente en un objeto String.
  • Path writeString(Path ruta, CharSequence texto, Charset cs, OpenOption... opciones): Escribe el texto en el archivo. Admite opciones de apertura como StandardOpenOption.CREATE y StandardOpenOption.APPEND.
  • List<String> readAllLines(Path ruta, Charset cs): Carga todas las líneas del fichero en una colección List<String> en memoria.

D. Procesamiento Funcional de Archivos Gigantes con Files.lines()

¿Qué ocurre si el archivo pesa 5 Gigabytes? Usar readAllLines() provocaría instantáneamente un error catastrófico OutOfMemoryError al intentar almacenar 5 GB de objetos en el Heap de la JVM. Para ficheros masivos se utiliza Files.lines(), que genera un flujo perezoso (Lazy Stream): las líneas se leen una a una del disco únicamente cuando el pipeline de operaciones funcionales las solicita.

⚠️ Regla Crítica: El Stream de Files.lines() DEBE cerrarse con try-with-resources

A diferencia de los Streams habituales de colecciones (como lista.stream()), el Stream<String> que produce Files.lines() mantiene abierto un descriptor de fichero en el núcleo del sistema operativo. Por tanto, es obligatorio envolverlo dentro de un try-with-resources para garantizar que el archivo se libere al finalizar la lectura.

AnalisisLogStreamingNIO.java JAVA 21 
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.stream.Stream;

public class AnalisisLogStreamingNIO {
    public static void auditarLogServidor(Path rutaLog) {
        // Files.lines abre el canal del SO: DEBE ir en el try()
        try (Stream<String> lineas = Files.lines(rutaLog, StandardCharsets.UTF_8)) {
            
            long totalErroresCriticos = lineas
                .filter(linea -> linea.contains("[ERROR]") || linea.contains("[FATAL]"))
                .filter(linea -> linea.contains("DatabaseConnectionException"))
                .peek(System.out::println) // Muestra cada línea coincidente
                .count(); // Operación terminal que consume el flujo de forma perezosa

            System.out.println("Total de fallos de base de datos encontrados: " + totalErroresCriticos);
            
        } catch (IOException e) {
            System.err.println("Fallo al procesar el archivo con NIO.2: " + e.getMessage());
        }
    }
}

3.3. Juegos de Caracteres (Charsets) y Trampas de Codificación

Un disco físico no entiende de letras, vocales con tilde ni caracteres especiales; únicamente almacena combinaciones de ceros y unos (bytes). La traducción entre una secuencia binaria y un carácter alfanumérico legible se rige por una tabla de correspondencia matemática denominada Juego de Caracteres (Charset).

  • ASCII (7 bits): Solo cubre 128 caracteres estándar en inglés (sin tildes, ñ ni símbolos como €).
  • ISO-8859-1 / Windows-1252 (ANSI, 8 bits): Añade caracteres de idiomas de Europa Occidental, pero asigna códigos incompatibles con otros alfabetos.
  • UTF-8 (Longitud variable, 1 a 4 bytes): El estándar absoluto de la industria moderna. Representa cualquier carácter del estándar universal Unicode siendo compatible hacia atrás con ASCII. Un carácter común en inglés ocupa 1 byte, pero una 'á' o una 'ñ' ocupan 2 bytes, y el símbolo del euro '€' ocupa 3 bytes.
❌ La Trampa del Charset por Defecto y el Mojibake

Si creas un new FileReader(archivo) o invocas Files.readAllLines(archivo) sin indicar el juego de caracteres, Java utiliza el valor del sistema anfitrión: Charset.defaultCharset().
• En un equipo de desarrollo Windows en español, el valor por defecto suele ser windows-1252.
• En un servidor Linux de despliegue o un contenedor Docker, suele ser UTF-8.
Consecuencia: Un archivo con caracteres españoles ("Camión", "Diseño") creado en Windows se leerá en Linux como texto corrupto (mojibake: "CamiÃ³n" o "DiseÃ±o").
Solución Obligatoria: Declarar siempre la constante StandardCharsets.UTF_8.

3.4. Ficheros Binarios y Flujos de Bytes (java.io)

Cuando los datos no representan texto sino estructuras de información binaria (ficheros comprimidos, imágenes, gráficos o valores numéricos primitivos), se utilizan flujos derivados de InputStream y OutputStream. Almacenar datos en binario elimina el sobrecoste de parseo textual y ahorra espacio físico en disco (un entero int siempre ocupa 4 bytes exactos frente a los 10 bytes que requeriría en texto).

A. Clases Base: FileInputStream y FileOutputStream

Concepto: Flujos fundamentales de bajo nivel que establecen una conexión directa con el canal físico del sistema operativo para leer y escribir secuencias de bytes individuales (valores numéricos de 0 a 255).

Instrucción / Método Parámetros Retorno Qué hace exactamente en disco / memoria
int read() throws IOException Ninguno int (0 a 255 o -1) Lee el siguiente byte físico del archivo y avanza el cabezal 1 posición. Devuelve -1 al alcanzar el Fin de Fichero (EOF).
int read(byte[] b, int off, int len) byte[] b, int off, int len int (bytes leídos) Lee un bloque de hasta len bytes del archivo y los transfiere directamente a la memoria RAM en el array b comenzando en el índice off.
void write(int b) throws IOException int b void Escribe los 8 bits menos significativos del entero en el archivo físico.
void write(byte[] b, int off, int len) byte[] b, int off, int len void Vuelca en bloque len bytes del array b hacia el medio de almacenamiento físico.

B. Flujos de Datos Tipados: DataOutputStream y DataInputStream

Concepto: Decoradores de flujos binarios que implementan las interfaces DataOutput y DataInput. Permiten escribir y leer variables primitivas de Java (int, double, boolean, etc.) y cadenas en formato UTF-8 modificado, utilizando el orden de bytes estándar de red (Big-Endian: el byte más significativo se escribe primero).

❌ Regla de Oro: El Contrato de Simetría y la Captura de EOFException

1. Simetría obligatoria: Los datos binarios no tienen separadores. Debes leer exactamente en el mismo orden e invocar las mismas instrucciones con las que escribiste. Si escribes writeInt() seguido de writeDouble(), pero al leer invocas primero readDouble(), Java mezclará los 4 bytes del entero con 4 bytes del double, corrompiendo la posición del puntero.
2. Detección de Fin de Archivo: readInt() o readDouble() no pueden devolver -1 ni null porque esos son números válidos. Por tanto, avisan del final lanzando una excepción java.io.EOFException. El bucle de lectura debe ser while(true) capturando canónicamente dicha excepción.

GestorTelemetriaDataStream.java JAVA 21 
import java.io.*;

public class GestorTelemetriaDataStream {

    public static void guardarMediciones(File archivo) {
        // Envolvemos FileOutputStream con BufferedOutputStream y DataOutputStream
        try (DataOutputStream dos = new DataOutputStream(
                new BufferedOutputStream(new FileOutputStream(archivo)))) {

            // Registro 1: ID sensor (int), Nombre (UTF), Temperatura (double), Alarma (boolean)
            dos.writeInt(101);                 // 4 bytes
            dos.writeUTF("Caldera Central");   // 2 bytes cabecera + 15 bytes texto = 17 bytes
            dos.writeDouble(82.45);            // 8 bytes
            dos.writeBoolean(true);            // 1 byte (alarma activa)

            // Registro 2: Sensor de refrigeración
            dos.writeInt(102);                 // 4 bytes
            dos.writeUTF("Rack Servidores A"); // 2 bytes + 17 bytes = 19 bytes
            dos.writeDouble(19.20);            // 8 bytes
            dos.writeBoolean(false);           // 1 byte (sin alarma)

            dos.flush();
            System.out.println("✅ Datos binarios volcados con éxito a disco.");

        } catch (IOException e) {
            System.err.println("Error al escribir datos tipados: " + e.getMessage());
        }
    }

    public static void leerMediciones(File archivo) {
        // Leemos con DataInputStream controlando el final mediante EOFException
        try (DataInputStream dis = new DataInputStream(
                new BufferedInputStream(new FileInputStream(archivo)))) {

            System.out.println("📡 Registros binarios recuperados:");
            while (true) {
                // Leemos en el orden estricto de escritura
                int id = dis.readInt();
                String nombre = dis.readUTF();
                double temp = dis.readDouble();
                boolean alarma = dis.readBoolean();

                System.out.printf("  Sensor [%d] %-18s | Temp: %6.2f ºC | Alarma: %s%n",
                                  id, nombre, temp, (alarma ? "⚠️ SÍ" : "OK"));
            }

        } catch (EOFException e) {
            // Fin natural del archivo binario
            System.out.println("🏁 Fin de fichero alcanzado correctamente.");
        } catch (IOException e) {
            System.err.println("Error de lectura: " + e.getMessage());
        }
    }
}

3.5. Ficheros de Acceso Aleatorio (RandomAccessFile)

En los flujos secuenciales convencionales, para acceder al registro número 10.000 es obligatorio leer primero los 9.999 anteriores. La clase java.io.RandomAccessFile rompe esta restricción: modela el fichero como un **gran array de bytes persistente en disco**, permitiendo desplazar un cabezal de lectura/escritura (Puntero de Archivo o File Pointer) de forma instantánea a cualquier coordenada en bytes.

A. Modos de Apertura en el Constructor

  • new RandomAccessFile(file, "r"): Modo solo lectura (Read-Only). Si el fichero no existe, lanza FileNotFoundException. Cualquier intento de escritura lanza IOException.
  • new RandomAccessFile(file, "rw"): Modo lectura y escritura (Read-Write). Si el fichero no existe en disco, lo crea automáticamente. Si existe, no borra su contenido: sitúa el puntero en el byte 0.
  • new RandomAccessFile(file, "rws") y "rwd": Modos sincronizados donde cada operación de escritura se sincroniza atómicamente a nivel de hardware en el disco físico.

C. La Necesidad de Registros de Longitud Fija y Cálculo de Offsets

Para que la función seek() pueda aterrizar con precisión matemática en el registro número $N$ sin necesidad de leer los anteriores, cada registro del archivo debe medir exactamente la misma cantidad de bytes:

$$\mathbf{Offset \ en \ bytes} = \text{Índice del Registro} \times \text{Tamaño Fijo del Registro}$$
⚠️ Por qué writeUTF() está prohibido en registros fijos de RandomAccessFile

Si escribes un String con writeUTF(), los bytes que ocupa variarán según el contenido del texto: "Ana" ocupará 5 bytes (2 de cabecera + 3 caracteres), mientras que "Constantinopla" ocupará 16 bytes. Esta variabilidad desajusta la cuadrícula y destruye la alineación de todos los registros siguientes.
Solución Técnica Obligatoria: Fijar siempre una cantidad fija de caracteres mediante StringBuffer.setLength() y escribirla con writeChars().

AlmacenArticulosRAF.java JAVA 21 
import java.io.File;
import java.io.IOException;
import java.io.RandomAccessFile;

public class AlmacenArticulosRAF {

    // Estructura fija: ID (4 bytes) + Nombre (10 chars = 20 bytes) + Precio (8 bytes) = 32 bytes
    public static final int TAMANO_REGISTRO = 32;
    public static final int MAX_CHARS_NOMBRE = 10;

    public static void escribirArticulo(RandomAccessFile raf, int posicion, int id, String nombre, double precio) throws IOException {
        // Saltamos directamente al byte inicial del registro deseado
        long offset = (long) posicion * TAMANO_REGISTRO;
        raf.seek(offset);

        // 1. ID: 4 bytes
        raf.writeInt(id);

        // 2. Nombre: exactamente 10 caracteres (20 bytes) usando StringBuffer
        StringBuffer sb = new StringBuffer(nombre);
        sb.setLength(MAX_CHARS_NOMBRE); // Rellena con '\0' o recorta si supera 10 caracteres
        raf.writeChars(sb.toString());

        // 3. Precio: 8 bytes
        raf.writeDouble(precio);
    }

    public static void modificarPrecioInSitu(File archivo, int posicion, double nuevoPrecio) {
        try (RandomAccessFile raf = new RandomAccessFile(archivo, "rw")) {
            // El campo precio empieza tras el ID (4 bytes) y el Nombre (20 bytes) = +24 bytes
            long offsetPrecio = ((long) posicion * TAMANO_REGISTRO) + 24;

            System.out.println("🎯 Saltando directamente al offset del precio: " + offsetPrecio);
            raf.seek(offsetPrecio);

            double precioAntiguo = raf.readDouble(); // Lee 8 bytes y avanza el puntero 8 bytes
            System.out.printf("Precio anterior: %.2f €%n", precioAntiguo);

            // ¡IMPORTANTE! readDouble() avanzó el cabezal. Debemos retroceder para sobreescribir:
            raf.seek(offsetPrecio);
            raf.writeDouble(nuevoPrecio); // Sobreescribe los 8 bytes sin tocar nada más del disco
            System.out.printf("✅ Precio actualizado in-situ a: %.2f €%n", nuevoPrecio);

        } catch (IOException e) {
            System.err.println("Error en acceso aleatorio: " + e.getMessage());
        }
    }
}

3.6. Serialización y Deserialización de Objetos en Java

La Serialización es el mecanismo nativo de Java que permite tomar un objeto vivo en la memoria RAM y convertir todo su grafo interno, atributos y referencias en un flujo lineal de bytes binarios. La Deserialización realiza el proceso inverso: lee esos bytes desde disco o red y reconstruye una réplica idéntica del objeto en RAM **sin invocar a los constructores ordinarios**.

A. Requisitos de la Entidad Serializable

  • Interfaz java.io.Serializable: Interfaz marcadora sin métodos que autoriza a la JVM a inspeccionar reflectivamente la clase. Si no se implementa, se lanza NotSerializableException.
  • Constante serialVersionUID: Identificador de 64 bits (long) que define la versión de la clase. Si se omite, la JVM calcula un hash automático; cualquier modificación posterior en la clase alterará el hash provocando InvalidClassException al intentar leer ficheros previamente guardados.
  • Modificador transient: Indica al motor de serialización que el campo marcado **no debe guardarse en disco** (contraseñas, tokens JWT, hilos Thread o conexiones Connection). Recupera el valor por defecto (null o 0) al deserializarse.

D. El Problema del Append y la Solución con MiObjectOutputStream

Si intentas añadir objetos a un archivo existente usando new ObjectOutputStream(new FileOutputStream(ruta, true)), el constructor escribirá una segunda cabecera mágica (0xACED0005) en mitad del archivo. Al leer posteriormente con ObjectInputStream, tras leer el primer objeto el parser encontrará los bytes de cabecera esperando datos, colapsando con:

java.io.StreamCorruptedException: invalid type code: AC

Para solucionarlo de forma profesional, creamos la subclase MiObjectOutputStream sobrescribiendo writeStreamHeader() en blanco:

SolucionAppendObjetos.java JAVA 21 
import java.io.*;

// Subclase que anula la escritura de la cabecera intermedia
class MiObjectOutputStream extends ObjectOutputStream {
    public MiObjectOutputStream(OutputStream out) throws IOException { super(out); }
    @Override
    protected void writeStreamHeader() throws IOException {
        // Al dejar este método vacío, NO se escribe la cabecera repetida 0xACED0005
    }
}

public class SolucionAppendObjetos {
    public static void anadirObjetoSeguro(File archivo, Object obj) {
        // Verificamos si el archivo ya existe Y contiene datos previos
        boolean yaTieneDatos = archivo.exists() && archivo.length() > 0;

        try {
            FileOutputStream fos = new FileOutputStream(archivo, true); // Modo append activado
            
            // Decisión inteligente de flujo:
            // - Si es la primera vez: ObjectOutputStream normal (escribe la cabecera requerida)
            // - Si ya tiene datos: MiObjectOutputStream (no escribe cabecera repetida)
            ObjectOutputStream oos = yaTieneDatos 
                    ? new MiObjectOutputStream(fos) 
                    : new ObjectOutputStream(fos);

            oos.writeObject(obj);
            oos.close();
            System.out.println("✅ Objeto añadido incrementalmente sin corromper el stream.");

        } catch (IOException e) {
            System.err.println("Error al persistir: " + e.getMessage());
        }
    }
}

import java.io.File;
import javax.xml.parsers.*;
import javax.xml.transform.*;
import javax.xml.transform.dom.DOMSource;
import javax.xml.transform.stream.StreamResult;
import org.w3c.dom.*;

public class GestorCompletoDOM {

    public static void crearCatalogoXml(File destino) throws Exception {
        DocumentBuilder builder = DocumentBuilderFactory.newInstance().newDocumentBuilder();
        Document doc = builder.newDocument(); // Documento nuevo en blanco

        // 1. Crear nodo raíz: 
        Element raiz = doc.createElement("catalogo");

        System.out.println("✅ Catálogo XML generado exitosamente con DOM.");
    }

    public static void modificarPreciosDOM(File origen) throws Exception {
        DocumentBuilder builder = DocumentBuilderFactory.newInstance().newDocumentBuilder();
        Document doc = builder.parse(origen);
        doc.getDocumentElement().normalize(); // Limpieza obligatoria

        NodeList productos = doc.getElementsByTagName("producto");

            Node n = productos.item(i);

            if (n.getNodeType() == Node.ELEMENT_NODE) {

                Element elemPrecio = (Element) elem.getElementsByTagName("precio").item(0);
                double precioActual = Double.parseDouble(elemPrecio.getTextContent());
                double precioNuevo = precioActual * 1.10; // Incremento del 10%
                elemPrecio.setTextContent(String.format("%.2f", precioNuevo).replace(',', '.'));
            }
        }

        // Guardamos las modificaciones sobre el mismo archivo
        Transformer tf = TransformerFactory.newInstance().newTransformer();
        tf.setOutputProperty(OutputKeys.INDENT, "yes");
        tf.transform(new DOMSource(doc), new StreamResult(origen));
        System.out.println("✅ Precios actualizados en disco tras modificación en RAM.");
    }
}

B. Manera 2: SAX (Simple API for XML)

Concepto: Analizador unidireccional y reactivo (*Push*). No construye ningún árbol en memoria; lee secuencialmente de arriba hacia abajo y dispara eventos que son procesados por los métodos de una clase que hereda de DefaultHandler. Es el estándar para archivos de cientos de megabytes o gigabytes donde DOM agotaría la memoria RAM.

Método Callback (DefaultHandler) Parámetros Cuándo se dispara y qué labor realizar
startDocument() Ninguno Se ejecuta exactamente una vez al comenzar a leer el archivo XML. Ideal para resetear listas y acumuladores.
startElement(uri, localName, qName, attributes) String uri, localName, qName, Attributes attributes Se dispara al encontrar una etiqueta de apertura (ej. <producto id="P-100">). qName da el nombre de la etiqueta. Se leen atributos con attributes.getValue("id") y se limpia el acumulador de texto.
characters(char[] ch, int start, int length) char[] ch, int start, int length Se dispara cuando lee texto dentro de una etiqueta. ⚠️ *¡Atención!* El parser puede llamar a este método varias veces seguidas para un mismo texto; **es obligatorio acumularlo con StringBuilder.append()**.
endElement(uri, localName, qName) String uri, localName, qName Se dispara al encontrar la etiqueta de cierre (ej. </producto>). Momento en el que se extrae el texto del acumulador, se parsea a su tipo y se añade a la colección o informe.
endDocument() Ninguno Se ejecuta al finalizar completamente el documento. Ideal para imprimir estadísticas o cerrar bases de datos.

import java.io.File;
import javax.xml.parsers.SAXParser;
import javax.xml.parsers.SAXParserFactory;
import org.xml.sax.Attributes;
import org.xml.sax.helpers.DefaultHandler;

public class AnalizadorCatalogoSAX {
    public static void procesarConSAX(File archivoXml) throws Exception {
        SAXParserFactory factory = SAXParserFactory.newInstance();
        SAXParser saxParser = factory.newSAXParser();

        DefaultHandler handler = new DefaultHandler() {
            private StringBuilder sb = new StringBuilder();
            private String idActual;
            private double precioActual;
            private boolean dentroDePrecio = false;

            @Override
            public void startElement(String uri, String localName, String qName, Attributes atts) {
                sb.setLength(0); // Limpiamos acumulador
                if (qName.equalsIgnoreCase("producto")) {
                    idActual = atts.getValue("id");
                } else if (qName.equalsIgnoreCase("precio")) {
                    dentroDePrecio = true;
                }
            }

            @Override
            public void characters(char[] ch, int start, int length) {
                sb.append(ch, start, length); // Acumulación estricta de caracteres
            }

            @Override
            public void endElement(String uri, String localName, String qName) {
                if (qName.equalsIgnoreCase("precio") && dentroDePrecio) {
                    precioActual = Double.parseDouble(sb.toString().trim());
                    dentroDePrecio = false;
                } else if (qName.equalsIgnoreCase("producto")) {
                    System.out.printf("⚡ [SAX Event] Producto ID: %s | Precio: %.2f €%n", idActual, precioActual);
                }
            }
        };

        System.out.println("Iniciando análisis SAX con 0 MB de consumo de árbol:");
        saxParser.parse(archivoXml, handler);
    }
}

import java.io.FileInputStream;
import javax.xml.stream.XMLInputFactory;
import javax.xml.stream.XMLStreamConstants;
import javax.xml.stream.XMLStreamReader;

public class LectorStAXPull {
    public static void buscarProductoPorId(String rutaXml, String idBuscado) throws Exception {
        XMLInputFactory factory = XMLInputFactory.newInstance();
        try (FileInputStream fis = new FileInputStream(rutaXml)) {
            XMLStreamReader reader = factory.createXMLStreamReader(fis);

            while (reader.hasNext()) {
                int evento = reader.next();
                if (evento == XMLStreamConstants.START_ELEMENT) {
                    if ("producto".equalsIgnoreCase(reader.getLocalName())) {
                        String id = reader.getAttributeValue(null, "id");
                        if (idBuscado.equals(id)) {
                            System.out.println("🎯 Producto encontrado con StAX: " + id);
                            break; // ¡VENTAJA DE STAX!: Detenemos el parseo inmediatamente sin leer el resto
                        }
                    }
                }
            }
            reader.close();
        }
    }
}

Nivel 3 (Avanzado / Profesional): Actualizador Transaccional con RandomAccessFile

Modifica directamente el registro de un producto en disco sin recorrer el archivo ni crear copias temporales.

ActualizadorStockRAF.java JAVA 21 
import java.io.File;
import java.io.IOException;
import java.io.RandomAccessFile;

public class ActualizadorStockRAF {
    // Registro: ID (int, 4 bytes) + Nombre (30 chars, 60 bytes) + Stock (int, 4 bytes) = 68 bytes
    public static final int TAM_REGISTRO = 68;

    public static boolean actualizarStock(File bdArticulos, int idProducto, int unidadesRestar) {
        try (RandomAccessFile raf = new RandomAccessFile(bdArticulos, "rw")) {
            // El ID determina la posición física exacta del registro: (id - 1) * 68
            long posRegistro = (long)(idProducto - 1) * TAM_REGISTRO;
            if (posRegistro + TAM_REGISTRO > raf.length()) {
                return false; // El producto no existe en el archivo
            }

            // Saltamos directamente a la posición del campo Stock (offset + 64 bytes)
            raf.seek(posRegistro + 64);
            int stockActual = raf.readInt();

            if (stockActual >= unidadesRestar) {
                raf.seek(posRegistro + 64); // Reposicionamos para sobreescribir
                raf.writeInt(stockActual - unidadesRestar);
                return true;
            }
            return false; // Stock insuficiente
        } catch (IOException e) {
            System.err.println("Error crítico en acceso directo: " + e.getMessage());
            return false;
        }
    }
}

     * Escribe un contenido textual de forma segura en disco, garantizando la existencia

    public static void guardarTextoSeguro(Path rutaFichero, String contenido) throws IOException {

6 Errores Habituales y Soluciones Técnicas

❌ Error 1: Fugas de Descriptores de Archivo del Sistema Operativo

¿Qué ocurre? Abrir flujos con new FileReader() o new FileInputStream() y cerrarlos manualmente al final del método con fr.close().
Causa técnica profunda: Si se produce cualquier excepción antes de llegar a la línea del close(), el manejador queda retenido en la tabla de descriptores del kernel. En Windows el archivo queda bloqueado (imposibilitando que otro proceso lo borre) y en Linux colapsa el servidor al alcanzar el límite del sistema (Too many open files).
Solución profesional: Emplear siempre try-with-resources.

❌ Error 2: Corrupción de Índices en RandomAccessFile por Cadenas Dinámicas

¿Qué ocurre? Escribir cadenas mediante writeUTF() en un fichero de acceso directo asumiendo un tamaño de registro constante.
Causa técnica profunda: writeUTF() escribe 2 bytes de cabecera más los bytes reales del texto. Al cambiar el tamaño del String entre un empleado y otro, la fórmula matemática $(N-1) \times \text{TAM}$ hace aterrizar el puntero en mitad de un dato numérico, corrompiendo la lectura.
Solución profesional: Asignar un número fijo de caracteres y rellenar los sobrantes con espacios en blanco.

❌ Error 3: El Desastre de la Doble Cabecera en la Serialización (modo append)

¿Qué ocurre? Usar new ObjectOutputStream(new FileOutputStream(file, true)) para añadir objetos al final de un archivo serializado existente.
Causa técnica profunda: Cada constructor de ObjectOutputStream inyecta una cabecera de 4 bytes (0xAC 0xED 0x00 0x05). Al leer el segundo bloque, la JVM espera un objeto y se topa con otra cabecera mágica, lanzando StreamCorruptedException.
Solución profesional: Crear una subclase que anule el método writeStreamHeader() en modo append.

❌ Error 4: Colapso OutOfMemoryError al procesar XML Masivos con DOM

¿Qué ocurre? Parsear un documento XML de 300 MB mediante DocumentBuilder.parse().
Causa técnica profunda: DOM instancia en la memoria RAM objetos Java para cada elemento, atributo, espacio en blanco y fragmento de texto. Un XML de 300 MB consume entre 1.2 y 1.8 GB de memoria Heap, colapsando la máquina virtual.
Solución profesional: Utilizar un parser reactivo orientado a eventos como SAX o StAX.

9 Resumen Clave de la Unidad

  • Streams: Abstracción de tubería unidireccional. Se dividen en flujos de Bytes (InputStream / OutputStream) y flujos de Caracteres (Reader / Writer).
  • Buffer: Imprescindible para el rendimiento; almacena 8 KB intermedios en RAM evitando peticiones microscópicas al disco.
  • NIO.2: Representa el estándar moderno basado en Path.of() y métodos atómicos de la clase Files. Para ficheros gigantes, Files.lines() procesa de forma perezosa mediante Streams.
  • StandardCharsets.UTF_8: Parámetro ineludible en toda lectura o escritura de texto para evitar la corrupción de tildes o caracteres multilingües (mojibake).
  • RandomAccessFile: Permite leer y escribir en cualquier posición arbitraria mediante seek(); requiere obligatoriamente que los registros tengan una longitud constante en bytes.
  • Serialización: Almacena objetos en disco con ObjectOutputStream. Requiere implementar Serializable, declarar serialVersionUID y usar transient para omitir datos sensibles. En modo append exige una subclase que anule writeStreamHeader().
  • XML: DOM construye el árbol en memoria RAM (ideal para edición de ficheros pequeños/medianos); SAX procesa eventos al vuelo con consumo cero de memoria (ideal para ficheros gigantes); JAXB mapea automáticamente clases POJO a etiquetas XML.

11 Glosario Técnico y Banco de Preguntas de Repaso

Glosario de Términos Fundamentales

  • Stream (Flujo): Canal de comunicación unidireccional y secuencial que transporta bytes o caracteres entre un origen y un destino.
  • Búfer: Área temporal de memoria RAM de alta velocidad diseñada para agrupar operaciones de lectura/escritura y reducir los accesos a disco físico.
  • Descriptor de Fichero (File Handle): Identificador numérico asignado por el núcleo del sistema operativo a cada archivo abierto por un proceso.
  • Charset: Mapa de correspondencia estandarizado entre secuencias binarias de bytes y caracteres legibles (alfanuméricos o gráficos).
  • Mojibake: Texto corrupto e ilegible resultante de decodificar una secuencia de bytes con un Charset diferente al que se utilizó para escribirlo.
  • Evaluación Perezosa (Lazy Evaluation): Estrategia de procesamiento donde los elementos de un flujo no se cargan en memoria hasta que la operación terminal los solicita.
  • Puntero de Fichero (File Pointer): Cursor numérico que señala el índice exacto de byte en el que tendrá lugar la siguiente lectura o escritura en un RandomAccessFile.
  • serialVersionUID: Identificador de versión de 64 bits que asegura que una clase Java coincide estructuralmente con los datos serializados que se intentan recuperar.
  • transient: Modificador reservado en Java que indica al motor de serialización que ignore dicho atributo al guardar el objeto.
  • DOM (Document Object Model): Especificación de parseo XML que crea en memoria RAM un árbol de objetos navegable bidireccionalmente.
  • SAX (Simple API for XML): Parser unidireccional basado en eventos que lee XML continuo con un consumo mínimo y constante de memoria RAM.
  • Marshalling / Unmarshalling: Proceso de transformar un grafo de objetos Java en un documento XML (Marshalling) y el proceso inverso (Unmarshalling) mediante JAXB.
