1. Contexto Profesional y Enunciado del Proyecto Evaluable · 10 Puntos

La entidad financiera Cantábrico Capital necesita renovar el núcleo de transacciones de su plataforma bancaria. El sistema debe operar contra una base de datos Oracle Database 23c mediante JDBC 4.3 y una piscina de conexiones de alto rendimiento gestionada por HikariCP.

Tu misión consiste en desarrollar la arquitectura de persistencia completa siguiendo los patrones de diseño Data Access Object (DAO), Data Transfer Object (DTO con Java Records) y Singleton para el DataSource.

📋 Requisitos Técnicos Obligatorios:
  • Entidad Cuenta (CuentaDTO): Record inmutable con campos id (Long), iban (String), titular (String), saldo (BigDecimal) y activa (Boolean).
  • Interfaz CuentaDAO: Métodos CRUD estándar (create, findById, findByIban, findAll, updateSaldo, deleteLogico).
  • Implementación CuentaDAOJdbc: Uso estricto de PreparedStatement, mapeo limpio de ResultSet a CuentaDTO y captura de SQLException relanzando excepciones de dominio PersistenceException.
  • Servicio Transaccional de Transferencias (TransferenciaService):
    • Método transferir(String ibanOrigen, String ibanDestino, BigDecimal importe) con control transaccional manual (setAutoCommit(false)).
    • Verificación atómica de saldo suficiente. Si el saldo es insuficiente, rollback inmediato.
    • Registro de la operación en la tabla movimientos_bancarios dentro de la misma transacción atómica.
  • HikariCP DataSource: Piscina configurada con 10 conexiones máximas y timeouts adecuados.
2. Rúbrica Analítica de Evaluación (Total: 10.0 Puntos) Criterios Oficiales
Criterio / RA Excelente (100%) Notable (75%) Aprobado (50%) Insuficiente (0%)
1. Conectividad y Pool HikariCP (2.0 pts)
CE2.a, CE2.h		 Pool HikariCP configurado a la perfección con singleton thread-safe y parámetros de timeout óptimos. Pool configurado correctamente pero con parámetros por defecto o código poco modular. Usa pool pero hay fugas de conexión ocasionales o mal cierre de recursos. Usa DriverManager directo en lugar de Connection Pool o no conecta.
2. Patrón DAO / DTO y Seguridad SQL (2.5 pts)
CE2.b, CE2.c		 Separación impecable DAO/DTO con Records, uso exclusivo de PreparedStatement y cero concatenación. Estructura DAO correcta con PreparedStatements pero modelos acoplados o sin Records. DAO funcional pero con mezcla de lógica de negocio o manejo deficiente de nulos. Usa Statement vulnerable a inyección SQL o no implementa el patrón DAO.
3. Gestión Transaccional ACID (3.5 pts)
CE2.d, CE2.g		 Atomicidad bancaria total con commit, rollback en catch, restore en finally y comprobación de saldo. Transacción implementada pero olvida restaurar setAutoCommit(true) o rollback parcial. Gestiona transacciones pero permite saldos negativos o fallos de consistencia. Opera en modo autoCommit dejando transferencias incompletas o corruptas.
4. Robustez y Excepciones (2.0 pts)
CE2.e, CE2.f		 Enmascaramiento de SQLException en excepciones de dominio y cierre impecable try-with-resources. Cierre correcto pero propaga SQLException directamente a la interfaz de usuario. Manejo genérico con e.printStackTrace() sin relanzar excepciones de dominio. Capturas vacías o fallos que congelan la aplicación sin diagnóstico.
