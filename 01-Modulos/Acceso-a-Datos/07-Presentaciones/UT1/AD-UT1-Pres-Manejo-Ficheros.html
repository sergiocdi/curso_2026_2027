🗺️ Mapa Conceptual: ¿Por qué gestionamos ficheros?

No toda la información reside en bases de datos. Los ficheros son indispensables para:

📂 Persistencia Local Rápida

Configuraciones de la aplicación (.properties, .env), cachés locales en disco y estados de sesión.

📊 Ingesta Masiva y Logs

Trazabilidad de servidores web (Apache/Nginx), pipelines de datos CSV e intercambio estructurado B2B con XML.

💡 Objetivo Profesional: Aprender a seleccionar la técnica exacta según el volumen, tipo de dato y requisitos de latencia y memoria RAM.
Bloque 1 · Texto Fundamentos I/O

🌊 1. El Concepto de Stream (Flujo) en Java

Un Stream es un conducto abstracto secuencial entre una fuente y un destino, aislando el hardware del código.

Familia de Flujos Clases Raíz Unidad Atómica Casos de Uso Primordiales
Flujos de Bytes InputStream / OutputStream 8 bits (Byte binario) Ficheros binarios, imágenes, audio, PDFs, red
Flujos de Caracteres Reader / Writer 16 bits (Carácter Unicode) Texto plano, archivos de configuración, CSV, JSON
⚠️ Regla de Oro: Los Reader/Writer traducen bytes a caracteres usando una tabla de codificación (*Charset*). Nunca leas un binario con un Reader: corromperás los datos.
Bloque 1 · Texto Rendimiento

⚡ 2. Búferes y el Patrón Decorador

Acceder al disco físico carácter a carácter colapsa la CPU con interrupciones del SO.

// Patrón Decorador: BufferedReader decora a FileReader aportando un buffer de 8 KB
try (BufferedReader br = new BufferedReader(new FileReader("datos.txt"))) {
    String linea;
    // readLine() lee bloques de disco a RAM y retorna null al llegar a EOF
    while ((linea = br.readLine()) != null) {
        System.out.println(linea);
    }
}
💡 readLine() consume el salto de línea pero no lo incluye. Para escribir texto con saltos de línea consistentes entre Windows y Linux, usa siempre bw.newLine().
Bloque 1 · Texto Java Moderno

🚀 3. La Revolución de Java NIO.2 (`java.nio.file`)

Reemplaza las limitaciones históricas de java.io.File con operaciones atómicas y rutas limpias:

Path & Paths

Representación inmutable y multiplataforma de rutas sin acoplar barras invertidas de Windows.

Path p = Paths.get("data", "logs", "app.log");
System.out.println(p.toAbsolutePath());

Files

Operaciones atómicas completas en una sola llamada:

Files.exists(p);
Files.createDirectories(p.getParent());
Files.copy(origen, destino, StandardCopyOption.REPLACE_EXISTING);
Bloque 1 · Texto Arquitectura

🔥 4. En Producción: readAllLines() vs Files.lines()

Método Retorno Consumo RAM Riesgo Uso Recomendado
Files.readAllLines() List<String> $O(N)$ (Carga todo en RAM) OutOfMemoryError en archivos grandes Configs y CSVs pequeños (< 20 MB)
Files.lines() Stream<String> $O(1)$ (Perezoso / Lazy) Ninguno (cierre obligatorio) Logs y ficheros masivos de Gigabytes 
// Procesa 10 GB consumiendo solo 25 MB de memoria RAM
try (Stream<String> stream = Files.lines(logPath, StandardCharsets.UTF_8)) {
    long errores = stream.filter(l -> l.contains(" 500 ")).count();
}
Bloque 2 · Binario Flujos Tipados

💾 5. Ficheros Binarios Tipados: `DataInputStream/OutputStream`

Guardar números como texto plano ("12345678") gasta 8 bytes y exige parseo. En binario, un entero ocupa siempre 4 bytes exactos.

Escritura

try (DataOutputStream dos = new DataOutputStream(
        new FileOutputStream("sensor.dat"))) {
    dos.writeInt(101);       // 4 bytes
    dos.writeDouble(23.75);   // 8 bytes
    dos.writeUTF("ACTIVO");   // Longitud + UTF-8
}

Lectura Secuencial

try (DataInputStream dis = new DataInputStream(
        new FileInputStream("sensor.dat"))) {
    int id = dis.readInt();
    double temp = dis.readDouble();
    String st = dis.readUTF();
}
⚠️ Regla Inquebrantable: Se deben leer los tipos exactamente en el mismo orden en que fueron grabados. El fin de archivo se detecta capturando EOFException.
Bloque 2 · Binario Acceso Aleatorio

🎯 6. Ficheros de Acceso Aleatorio: `RandomAccessFile`

Trata el fichero como un gran array de bytes en disco. Permite saltar a cualquier posición sin leer el archivo desde el inicio.

  • Modos de apertura: "r" (solo lectura) y "rw" (lectura y escritura).
  • Puntero de Fichero: seek(posicionBytes) y getFilePointer().
try (RandomAccessFile raf = new RandomAccessFile("empleados.bin", "rw")) {
    // Si cada registro mide exactamente 50 bytes:
    int idEmpleado = 3;
    long offset = (idEmpleado - 1) * 50L;
    
    raf.seek(offset);                 // Salto directo en nanosegundos
    int salarioActual = raf.readInt();
    
    raf.seek(offset);                 // Reubica el puntero para modificar in-situ
    raf.writeInt(salarioActual + 200); // Actualización sin reescribir el resto del fichero
}
Bloque 2 · Binario POJOs en Disco

📦 7. Serialización de Objetos en Java

Convierte el grafo completo de un objeto en memoria en una secuencia lineal de bytes transportable o almacenable.

Requisitos de la Entidad

  • Implementar java.io.Serializable.
  • Definir serialVersionUID = 1L;.
  • Usar transient para campos que NO deban guardarse (passwords, conexiones).

Canales ObjectStream

// Escritura
ObjectOutputStream oos = new ObjectOutputStream(fos);
oos.writeObject(listaAlumnos);

// Lectura (Deserialización)
ObjectInputStream ois = new ObjectInputStream(fis);
List<Alumno> list = (List<Alumno>) ois.readObject();
⚠️ Si cambias la clase sin definir serialVersionUID explícito, Java lanzará InvalidClassException al leer datos guardados anteriormente.
Bloque 3 · XML Datos Estructurados

📑 8. Tratamiento de XML en Java: Los 3 Enfoques

🌳 DOM

Document Object Model

Carga el documento completo en memoria en un árbol de nodos navegable. Ideal para consultar y modificar ficheros medianos (< 20 MB).

⚡ SAX

Simple API for XML

Basado en eventos y callbacks (startElement, endElement). Memoria constante $O(1)$. Solo lectura secuencial para XMLs masivos.

🪄 JAXB

Java Architecture for XML Binding

Mapeo declarativo mediante anotaciones (@XmlRootElement). Convierte POJOs a XML (*Marshaller*) automáticamente.

Bloque 3 · XML DOM en Acción

🌳 9. Lectura y Escritura con DOM (`DocumentBuilder` & `Transformer`)

// 1. Construir el árbol en memoria RAM
DocumentBuilder builder = DocumentBuilderFactory.newInstance().newDocumentBuilder();
Document doc = builder.parse(new File("alumnos.xml"));
doc.getDocumentElement().normalize();

// 2. Navegación por etiquetas
NodeList lista = doc.getElementsByTagName("alumno");
for (int i = 0; i < lista.getLength(); i++) {
    Element elem = (Element) lista.item(i);
    System.out.println(elem.getAttribute("dni") + " - " + 
                       elem.getElementsByTagName("nombre").item(0).getTextContent());
}

// 3. Volcado a disco con Transformer
Transformer t = TransformerFactory.newInstance().newTransformer();
t.setOutputProperty(OutputKeys.INDENT, "yes");
t.transform(new DOMSource(doc), new StreamResult(new File("salida.xml")));
Bloque 3 · XML SAX & JAXB

⚡ 10. SAX por Eventos y JAXB Declarativo

SAX: `DefaultHandler`

No carga nada en RAM; avisa al encontrar etiquetas:

class MiHandler extends DefaultHandler {
    public void startElement(String uri, String localName, 
                             String qName, Attributes atts) {
        if (qName.equals("alumno")) {
            System.out.println(atts.getValue("dni"));
        }
    }
}

JAXB: Mapeo Automático

Sin manipular nodos XML manualmente:

@XmlRootElement
public class Alumno {
    @XmlAttribute private String dni;
    @XmlElement private String nombre;
}

// Marshaller: Objeto -> XML
JAXBContext ctx = JAXBContext.newInstance(Alumno.class);
ctx.createMarshaller().marshal(alumno, new File("alumno.xml"));
